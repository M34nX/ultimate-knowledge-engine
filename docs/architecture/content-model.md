# Content Model

## Stable identity

Every concept, lesson, exercise, language profile, and reference should receive a globally unique, stable ID. IDs must not depend on translated titles.

Examples:
- `cs.algorithms.binary-search`
- `python.functions.parameters`
- `web.http.request-methods`

Never reuse an ID for a different concept. If content is merged or split, preserve redirects or explicit supersession records.

## Content types

| Type | Purpose |
|---|---|
| Concept | One reusable unit of knowledge |
| Lesson | A sequenced teaching experience with objectives |
| Exercise | A task that assesses application |
| Language profile | Scope, versions, paradigms, tooling, and official references |
| Reference | Traceable external source and reuse constraints |
| Roadmap | Ordered learning outcomes and prerequisites |
| Project | Applied work with acceptance criteria |

## Metadata

Capture, where applicable: ID, title, locale, type, domain, tags, lifecycle status, target level, prerequisites, learning objectives, version scope, sources, translation status, and review dates.

## Lifecycle

Draft → Reviewed → Verified → Published → Outdated or Deprecated. See the content lifecycle standard.
