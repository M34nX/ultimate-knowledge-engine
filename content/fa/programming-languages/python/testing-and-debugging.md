# آزمون‌نویسی و اشکال‌زدایی در پایتون

## ۱. چرا آزمون می‌نویسیم؟

آزمون خودکار بررسی می‌کند برنامه برای ورودی‌های مشخص، رفتار مورد انتظار را دارد. آزمون خوب فقط مسیر معمول را بررسی نمی‌کند؛ ورودی مرزی و حالت خطا را نیز در نظر می‌گیرد.

## ۲. آزمون کوچک با assert

```python
def add(a, b):
    return a + b

assert add(2, 3) == 5
assert add(-1, 1) == 0
```

`assert` برای بررسی فرض‌ها در نمونه‌های کوچک مناسب است. آزمون‌های پایدار پروژه بهتر است با چارچوب آزمون‌نویسی اجرا شوند؛ زیرا گزارش‌دهی و سازمان‌دهی بهتری دارند.

## ۳. آزمون با unittest

فایلی به نام `test_math_tools.py` بسازید:

```python
import unittest

def add(a, b):
    return a + b

class TestAdd(unittest.TestCase):
    def test_positive_numbers(self):
        self.assertEqual(add(2, 3), 5)

    def test_negative_and_positive(self):
        self.assertEqual(add(-2, 2), 0)

if __name__ == "__main__":
    unittest.main()
```

آزمون‌ها را از پوشه پروژه با دستور `python -m unittest` اجرا کنید. ساختار نام‌گذاری متعارف به کشف آزمون‌ها کمک می‌کند.

## ۴. طراحی آزمون

برای یک تابع، این موارد را بررسی کنید:
- ورودی معمول و معتبر؛
- کمینه و بیشینه دامنه؛
- ورودی خالی یا تکراری؛
- ورودی نامعتبر و نوع استثنای مورد انتظار؛
- شرایطی که ممکن است باعث خطای منطقی شوند.

آزمون باید مستقل، تکرارپذیر و تا جای ممکن بدون وابستگی به شبکه یا سرویس بیرونی باشد.

## ۵. روش اشکال‌زدایی

۱. خطا را بازتولید کنید.
۲. پیام خطا و traceback را از آخر به ابتدای زنجیره بررسی کنید.
۳. کوچک‌ترین ورودی‌ای را پیدا کنید که مشکل را ایجاد می‌کند.
۴. مقدار متغیرها و فرض‌های تابع را مرحله‌به‌مرحله بررسی کنید.
۵. پس از اصلاح، آزمون بازگشتی بنویسید تا خطا دوباره برنگردد.

برای مشاهده مرحله‌ای اجرای برنامه می‌توان از debugger محیط توسعه یا ماژول استاندارد `pdb` استفاده کرد.

## ۶. آزمون خوب چه ویژگی دارد؟

- نام آزمون هدف آن را روشن می‌کند.
- هر آزمون یک رفتار مشخص را بررسی می‌کند.
- نتیجه به زمان اجرا، شبکه یا داده واقعی وابسته نیست.
- برای خطاها و ورودی مرزی هم آزمون وجود دارد.
- آزمون‌ها سریع و قابل تکرارند.

## ۷. خطاهای رایج

- آزمونی که فقط کد را اجرا می‌کند اما نتیجه را بررسی نمی‌کند.
- آزمون وابسته به ترتیب اجرای آزمون‌های دیگر.
- استفاده از داده واقعی یا حساس.
- تغییر کد و حذف آزمون شکست‌خورده به‌جای فهم علت آن.

## ۸. تمرین

۱. برای تابعی که میانگین فهرست عددها را محاسبه می‌کند، آزمون معمول و ورودی خالی طراحی کنید.
۲. تابع تبدیل دما را با چند مقدار مرزی آزمایش کنید.
۳. یک خطای منطقی ساده ایجاد کنید، آن را بازتولید و سپس اصلاح کنید.
