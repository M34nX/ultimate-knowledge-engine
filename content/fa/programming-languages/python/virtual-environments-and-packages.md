# محیط مجازی و نصب بسته‌ها در پایتون

## ۱. چرا محیط مجازی؟

هر پروژه ممکن است به نسخه‌ها و بسته‌های متفاوتی نیاز داشته باشد. نصب همه وابستگی‌ها در یک محیط مشترک می‌تواند باعث ناسازگاری شود. محیط مجازی (Virtual environment) مسیر نصب و اجرای وابستگی‌های پروژه را جدا می‌کند.

## ۲. ایجاد محیط با venv

در پوشه پروژه اجرا کنید:

```bash
python -m venv .venv
```

سپس محیط را فعال کنید.

در Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

در Linux و macOS:

```bash
source .venv/bin/activate
```

پس از فعال‌سازی، اجرای `python` و `pip` معمولاً به محیط مجازی همین پروژه اشاره می‌کند. برای اطمینان، مسیر اجرایی را بررسی کنید.

## ۳. نصب بسته با pip

برای نمونه، بسته‌ای را در صورت نیاز پروژه نصب کنید:

```bash
python -m pip install requests
```

استفاده از `python -m pip` کمک می‌کند pip متعلق به همان مفسر پایتون اجرا شود.

## ۴. ثبت وابستگی‌ها

برای پروژه ساده می‌توانید وابستگی‌ها را در فایل `requirements.txt` ثبت کنید:

```text
requests==2.32.0
```

عدد نسخه در این نمونه صرفاً نمونه قالب است؛ پیش از استفاده، نسخه سازگار و به‌روز را از منبع رسمی بسته بررسی کنید. برای بازسازی محیط:

```bash
python -m pip install -r requirements.txt
```

در پروژه‌های بزرگ‌تر، روش قفل‌کردن نسخه‌ها و مدیریت بسته ممکن است به ابزارهای تخصصی‌تری نیاز داشته باشد.

## ۵. فایل‌ها و عادت‌های مناسب

- پوشه `.venv/` را معمولاً در `.gitignore` قرار دهید.
- خود محیط مجازی را در مخزن Git ثبت نکنید.
- فایل وابستگی‌ها و توضیح روش نصب را ثبت کنید.
- بسته‌های غیرضروری را اضافه نکنید.
- وابستگی‌های پروژه را از مراجع رسمی و قابل اعتماد دریافت کنید.

## ۶. خطاهای رایج

- نصب بسته در مفسری غیر از مفسر پروژه.
- فراموش‌کردن فعال‌سازی محیط مجازی.
- ثبت‌کردن پوشه حجیم و محلی `.venv` در Git.
- نصب نسخه نامتناسب بدون بررسی سازگاری.
- اشتباه گرفتن نام import با نام بسته نصب‌شونده؛ این دو همیشه یکسان نیستند.

## ۷. تمرین

۱. برای یک پوشه آزمایشی محیط مجازی بسازید.
۲. یک بسته سبک و موردنیاز نصب کنید و نسخه آن را بررسی کنید.
۳. وابستگی‌ها را ثبت و در محیط تازه بازیابی کنید.
