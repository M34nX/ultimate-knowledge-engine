# ایندکس و برنامهٔ اجرای پرس‌وجو

## ۱. ایندکس چه می‌کند؟

ایندکس ساختار کمکی‌ای است که به پایگاه داده کمک می‌کند بعضی ردیف‌ها را بدون پیمایش کامل جدول پیدا کند. ایندکس روی ستون‌هایی که زیاد در شرط جست‌وجو یا اتصال استفاده می‌شوند می‌تواند مفید باشد.

```sql
CREATE INDEX idx_students_name
ON students (name);
```

ساخت ایندکس برای هر ستون توصیه نمی‌شود؛ ایندکس فضای ذخیره‌سازی می‌گیرد و درج، حذف و به‌روزرسانی را پرهزینه‌تر می‌کند.

## ۲. برنامهٔ اجرا

`EXPLAIN` نشان می‌دهد PostgreSQL برای اجرای query چه برنامه‌ای انتخاب کرده است:

```sql
EXPLAIN
SELECT *
FROM students
WHERE student_id = 101;
```

ممکن است برنامه‌ریز از اسکن ترتیبی (Seq Scan) یا اسکن ایندکس استفاده کند. انتخاب به آمار جدول، گزینش‌پذیری شرط، هزینه‌ها و تنظیمات وابسته است.

## ۳. EXPLAIN ANALYZE

`EXPLAIN ANALYZE` query را واقعاً اجرا می‌کند و زمان و تعداد ردیف‌های مشاهده‌شده را گزارش می‌دهد. برای queryهایی که تغییر داده انجام می‌دهند، اجرا می‌تواند اثر جانبی داشته باشد؛ روی محیط آزمایشی و دادهٔ غیرحساس کار کنید.

## ۴. روش بهینه‌سازی

۱. ابتدا query و رفتار درست آن را مشخص کنید.
۲. با دادهٔ نماینده، زمان و برنامهٔ اجرای آن را بررسی کنید.
۳. گلوگاه را شناسایی کنید.
۴. یک تغییر در هر مرحله انجام دهید.
۵. دوباره اندازه‌گیری و نتیجه را مقایسه کنید.

## ۵. خطاهای رایج

- ساختن ایندکس برای هر ستون بدون سنجش.
- فرض اینکه استفاده از ایندکس همیشه سریع‌تر است.
- بهینه‌سازی بر اساس حدس به‌جای اندازه‌گیری.
- نادیده‌گرفتن هزینهٔ به‌روزرسانی ایندکس و فضای ذخیره‌سازی.
- مقایسهٔ اجرای اول و بعدی بدون توجه به cache و آمار.

## ۶. تمرین

۱. برای ستون جست‌وجوشونده یک ایندکس آزمایشی بسازید.
۲. خروجی EXPLAIN را پیش و پس از ساخت ایندکس مقایسه کنید.
۳. توضیح دهید چرا ایندکس اضافه می‌تواند سرعت درج را کاهش دهد.
