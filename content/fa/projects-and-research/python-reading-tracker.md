# پروژهٔ پایانی پایتون: مدیریت کتابخانهٔ شخصی

## مسئله

یک برنامهٔ خط فرمان بسازید که به کاربر امکان دهد فهرست کتاب‌های شخصی خود را مدیریت کند. برنامه باید بتواند کتاب اضافه کند، کتاب‌ها را نمایش دهد، بر اساس عنوان جست‌وجو کند و رکوردی را حذف کند. اطلاعات پس از بسته‌شدن برنامه باقی بمانند.

## محدوده و فرض‌ها

- پروژه برای یادگیری است و از دادهٔ ساختگی استفاده می‌کند.
- نسخهٔ نخست فقط در یک رایانه و برای یک کاربر اجرا می‌شود.
- نیاز به پایگاه داده، حساب کاربری، اتصال شبکه یا رابط گرافیکی نیست.
- فایل داده را در پوشهٔ دادهٔ برنامه نگه دارید و پیش از بازنویسی، خطر از دست‌رفتن داده را در نظر بگیرید.

## مدل داده

هر کتاب می‌تواند فیلدهای زیر را داشته باشد:

| فیلد | نوع پیشنهادی | توضیح |
|---|---|---|
| id | رشته | شناسهٔ یکتا درون برنامه |
| title | رشته | عنوان کتاب |
| author | رشته | نویسنده |
| year | عدد صحیح یا null | سال انتشار، در صورت معلوم‌بودن |
| read | بولی | آیا کتاب خوانده شده است؟ |

نمونهٔ یک رکورد JSON:

```json
{
  "id": "book-001",
  "title": "The Hobbit",
  "author": "J. R. R. Tolkien",
  "year": 1937,
  "read": false
}
```

## نیازمندی‌های عملکردی

۱. افزودن کتاب با عنوان و نویسندهٔ غیرخالی.
۲. نمایش همهٔ کتاب‌ها با وضعیت خوانده‌شده یا خوانده‌نشده.
۳. جست‌وجوی عنوان بدون حساسیت به بزرگی و کوچکی حروف.
۴. حذف کتاب با شناسه.
۵. ذخیره و بازیابی داده‌ها از JSON.
۶. نمایش پیام روشن هنگام نبود فایل یا خراب‌بودن محتوای ذخیره‌شده.
۷. جلوگیری از حذف تصادفی همهٔ داده‌ها با عملیات مبهم.

## ساختار پیشنهادی پوشه‌ها

```text
reading_tracker/
    main.py
    models.py
    storage.py
    services.py
    tests/
        test_services.py
    data/
        books.json
    README.md
```

این ساختار فقط یک پیشنهاد است؛ برای نسخهٔ بسیار کوچک می‌توان از فایل‌های کمتری استفاده کرد، اما جداسازی ذخیره‌سازی از منطق برنامه، آزمون را آسان‌تر می‌کند.

## مراحل انجام

### مرحلهٔ ۱: مدل و دادهٔ نمونه

ساختار کتاب را تعریف کنید. چند رکورد ساختگی بسازید و بررسی کنید داده‌ها چه زمانی معتبرند.

### مرحلهٔ ۲: عملیات اصلی

توابع جداگانه برای افزودن، جست‌وجو، فهرست‌کردن و حذف بسازید. هر تابع یک مسئولیت مشخص داشته باشد.

### مرحلهٔ ۳: ذخیره‌سازی

از ماژول استاندارد `json` و `pathlib` استفاده کنید. خواندن و نوشتن فایل را در یک ماژول مستقل قرار دهید.

### مرحلهٔ ۴: اعتبارسنجی و خطا

عنوان خالی را رد کنید. نبود فایل را از JSON خراب تفکیک کنید. پیام خطا نباید اطلاعات داخلی یا مسیرهای حساس غیرضروری را افشا کند.

### مرحلهٔ ۵: رابط خط فرمان

یک منوی ساده با گزینه‌های افزودن، نمایش، جست‌وجو، حذف و خروج بسازید. ورودی ناشناخته باید پیام راهنما بدهد و برنامه را ناخواسته متوقف نکند.

### مرحلهٔ ۶: آزمون و مستندسازی

برای منطق اصلی آزمون بنویسید. راه‌اندازی، اجرای برنامه، محل فایل داده و محدودیت‌های شناخته‌شده را در README ثبت کنید.

## معیار پذیرش

- کتاب جدید پس از اجرای مجدد برنامه همچنان موجود باشد.
- جست‌وجوی نتیجه‌دار و بی‌نتیجه درست عمل کند.
- حذف شناسهٔ ناموجود خطای کنترل‌شده داشته باشد.
- عنوان خالی ذخیره نشود.
- فایل دادهٔ خراب باعث توقف بی‌توضیح برنامه نشود.
- آزمون‌ها حداقل عملیات اصلی و حالت‌های مرزی را پوشش دهند.
- نصب و اجرای پروژه از روی راهنمای آن ممکن باشد.

## ایده‌های توسعه

- فیلتر کتاب‌های خوانده‌شده و خوانده‌نشده.
- مرتب‌سازی بر اساس عنوان یا سال.
- خروجی CSV برای تهیهٔ گزارش.
- برچسب و دسته‌بندی کتاب‌ها.
- رابط گرافیکی پس از تکمیل نسخهٔ خط فرمان.
