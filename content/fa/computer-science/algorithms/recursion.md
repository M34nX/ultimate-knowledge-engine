# بازگشت در طراحی الگوریتم

## ۱. بازگشت چیست؟

در روش بازگشتی، تابع برای حل مسئله، نسخهٔ کوچک‌تری از همان مسئله را حل می‌کند. هر تعریف بازگشتی به دو بخش نیاز دارد:
- **حالت پایه:** مسئله‌ای کوچک که پاسخ آن مستقیم معلوم است.
- **گام بازگشتی:** مسئله را به نمونه‌ای کوچک‌تر تبدیل می‌کند.

اگر حالت پایه یا کاهش اندازهٔ مسئله درست نباشد، تابع ممکن است بی‌پایان فراخوانی شود.

## ۲. مثال محاسبهٔ مجموع

```python
def sum_to(n):
    if n <= 0:
        return 0
    return n + sum_to(n - 1)

print(sum_to(4))  # 10
```

هر فراخوانی مقدار n را یک واحد کاهش می‌دهد و سرانجام به حالت پایه می‌رسد.

## ۳. فاکتوریل

```python
def factorial(n):
    if n < 0:
        raise ValueError("n must be non-negative")
    if n in (0, 1):
        return 1
    return n * factorial(n - 1)
```

تعریف ریاضی فاکتوریل برای n نامنفی چنین است: ۰! برابر ۱ و n! برابر n ضرب در (n-1)!.

## ۴. هزینه و پشتهٔ فراخوانی

هر فراخوانی تابع اطلاعاتی مانند متغیرهای محلی را در پشتهٔ فراخوانی نگه می‌دارد. بنابراین بازگشت عمیق ممکن است حافظه مصرف کند و به محدودیت عمق بازگشت برسد. برای بسیاری از پیمایش‌ها و پردازش‌های خطی، حلقهٔ تکراری گزینهٔ مناسبی است.

## ۵. چه زمانی بازگشت مناسب است؟

درخت‌ها، تقسیم و غلبه و ساختارهای بازگشتی مسئله‌ها می‌توانند با بازگشت خواناتر شوند. با این حال، باید عمق، پیچیدگی زمانی و احتمال محاسبهٔ تکراری زیرمسئله‌ها را تحلیل کرد.

## ۶. خطاهای رایج

- نبود حالت پایه.
- کوچک‌نشدن مسئله در هر فراخوانی.
- فراموش‌کردن اعتبارسنجی ورودی.
- محاسبهٔ مکرر زیرمسئله‌های یکسان، بدون memoization یا روش مناسب.

## ۷. تمرین

۱. تابعی بازگشتی برای جمع اعداد یک فهرست بنویسید.
۲. تابع فاکتوریل را برای صفر، یک و عدد منفی آزمایش کنید.
۳. توضیح دهید چرا پیاده‌سازی بازگشتی فیبوناچی ساده، محاسبهٔ تکراری زیادی دارد.
