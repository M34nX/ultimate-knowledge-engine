# وب چگونه کار می‌کند؟ HTTP و مدل درخواست/پاسخ

## ۱. مرورگر و سرور

در مدل رایج وب، مرورگر (client) درخواستی برای یک منبع می‌فرستد و سرور به آن پاسخ می‌دهد. منبع می‌تواند صفحهٔ HTML، تصویر، فایل CSS یا دادهٔ JSON باشد. این ارتباط معمولاً با پروتکل HTTP انجام می‌شود.

## ۲. اجزای URL

یک URL می‌تواند scheme، میزبان، پورت، مسیر، query و fragment داشته باشد:

```text
https://example.com:443/courses?level=beginner#intro
```

- `https`: طرح ارتباط؛
- `example.com`: میزبان؛
- `443`: پورت؛
- `/courses`: مسیر؛
- `level=beginner`: پارامتر query؛
- `intro`: fragment که معمولاً در سمت مرورگر برای بخش صفحه به‌کار می‌رود.

## ۳. درخواست HTTP

یک درخواست شامل روش (method)، مسیر، سرآیندها (headers) و در برخی موارد بدنه (body) است. روش‌های رایج:
- GET برای دریافت نمایش یا داده؛
- POST برای ارسال داده یا ایجاد منبع در بسیاری از APIها؛
- PUT برای جایگزینی یک منبع؛
- PATCH برای اعمال تغییر جزئی؛
- DELETE برای درخواست حذف منبع.

معنای دقیق هر روش باید با قرارداد API و استاندارد HTTP سنجیده شود.

## ۴. پاسخ و کد وضعیت

پاسخ سرور شامل کد وضعیت، سرآیندها و گاهی بدنه است:
- 200: درخواست موفق؛
- 201: منبع ایجاد شد؛
- 301 یا 302: انتقال مسیر؛
- 400: درخواست نامعتبر؛
- 401: احراز هویت لازم یا ناموفق؛
- 403: دسترسی مجاز نیست؛
- 404: منبع پیدا نشد؛
- 500: خطای داخلی سرور.

کد وضعیت به‌تنهایی جزئیات همهٔ خطاها را بیان نمی‌کند؛ بدنه و سرآیندهای پاسخ هم اهمیت دارند.

## ۵. HTTPS

HTTPS ارتباط HTTP را با TLS محافظت می‌کند. این کار به محرمانگی و یکپارچگی داده در مسیر و احراز هویت سرور کمک می‌کند. HTTPS به‌تنهایی تضمین نمی‌کند محتوای سایت درست، معتبر یا بی‌خطر باشد.

## ۶. مسیر کلی یک درخواست

۱. مرورگر نام میزبان را به آدرس شبکه تبدیل می‌کند.
۲. ارتباط شبکه برقرار می‌شود.
۳. در HTTPS، مذاکرهٔ TLS انجام می‌شود.
۴. درخواست HTTP فرستاده می‌شود.
۵. سرور پاسخ می‌دهد و مرورگر منبع را پردازش می‌کند.

جزئیات شبکه‌ای در مسیر سیستم‌ها و شبکه به‌صورت مستقل بررسی می‌شود.

## ۷. تمرین

۱. اجزای URL نمونهٔ درس را جدا کنید.
۲. برای دریافت یک فهرست درس‌ها، روش و نوع پاسخ مناسب را انتخاب کنید.
۳. تفاوت 401 و 403 را با زبان خود توضیح دهید.
